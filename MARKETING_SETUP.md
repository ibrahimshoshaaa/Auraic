# Marketing and traffic

Apply `npx prisma migrate deploy` to the intended database before enabling the release. The migration adds only StoreVisit; it does not modify business records. Do not use reset/db push on production.

Owners configure IDs in Dashboard → Storefront → التسويق والزيارات. Empty IDs disable loading. No arbitrary scripts or access tokens are accepted. Meta and TikTok browser scripts load only after advertising consent; use Advertising preferences to revoke and reset that choice. The integration does not send names, phones, email, addresses or advanced matching fields. Purchase means accepted order, including COD or an unverified transfer, not collected payment. Pixel events are best effort: blocked scripts and visitors declining consent reduce totals.

Traffic is separate: random per-tab session IDs, allowlisted paths without query strings, and view IDs used for idempotency. Counts are approximate sessions and page views, not unique people. Reloads count as views. Known bots are excluded, request limits apply, and entries older than 90 days are pruned when recording new views. Reports are store-scoped and require reports.read. Tracking begins at deployment; there is no historical backfill.

Verification: use owned test Pixels in Meta Test Events/Meta Pixel Helper and TikTok Test Events/Pixel Helper. Accept consent, visit a product, add an item and enter checkout. Confirm exactly one PageView per navigation, ViewContent, AddToCart, InitiateCheckout and one Purchase on a successfully accepted test order. Failed requests must not send Purchase. Refresh confirmation and retry the same order to check deduplication. Decline/reset consent and confirm no advertising requests. Compare traffic reports with scripted navigation; access via another store must not reveal traffic. Browser IDs can be forged; these counts are not billing/fraud evidence.

Current validation: TypeScript, unit/API tests, production build, and lint. Consent refusal/acceptance and purchase deduplication were exercised in a real browser with mocked provider functions in a local-only harness; no real events were sent. The additive SQL migration, duplicate view handling and store-scoped counts were verified on isolated Neon branch `codex-pixel-analytics-test` in the original project. Direct application-to-Neon networking was unavailable from the executor, so a full live HTTP/database flow could not be completed. API validation/origin/bot/rate/error paths were tested with a mocked persistence layer. No production migration was run and no business data in the source branch or client database was changed.

The Neon test branch remains available for inspection. No real Pixel IDs have been supplied; platform receipt in Meta/TikTok Test Events remains the final activation check. The feature records new traffic only after migration and deployment.


Traffic report details: hourly (24-hour filter) or Cairo-calendar daily charts, per-period sessions/views, pages per session, sessions reaching checkout, last-15-minute activity, single-page sessions and page-level session counts/share/last seen. Product names are resolved within the signed-in store. Comparisons use equal rolling windows and remain unavailable until a complete prior window exists after the migration timestamp and within 90-day retention. Opening checkout is not an order or a purchase conversion. Daily session totals can exceed period sessions when the same session spans days. Device, country, referrer and duration are not collected. No schema changes are needed for these report additions.
