# Auraic — متجر العطور ولوحة الإدارة

مشروع مستقل مبني على لوحة Auraic الحالية، مع متجر إلكتروني للعملاء داخل نفس تطبيق Next.js وقاعدة PostgreSQL. مرجع تجربة الشراء هو dahab-store، بهوية Auraic الكحلي والذهبي.

## الصفحات
- `/`: الرئيسية، بانرات متعددة، الأقسام والمنتجات المميزة.
- `/products` و`/products/[id]`: البحث والتصفية والترتيب، صور المنتج وأحجامه ووصفه.
- `/cart` و`/checkout`: حقيبة محفوظة على الجهاز، رسوم الشحن، وطلب بالدفع عند الاستلام.
- `/shipping` و`/returns` و`/contact`: السياسات ووسائل التواصل التي يحددها المالك.
- `/login` و`/dashboard`: الإدارة الحالية بكل المخزون والوصفات والمصروفات والطلبات والتقارير.
- `/dashboard/storefront`: نشر المنتجات وإدارة الصور والوصف والأقسام والبانرات والشحن وواتساب.

## التشغيل
```bash
npm ci
npm run db:generate
npx prisma migrate deploy
npm run dev
```
انسخ `.env.example` إلى `.env`، وحدد متغيراتك. تفاصيل النشر وحساب المالك في [STOREFRONT_SETUP.md](STOREFRONT_SETUP.md).

## الطلبات والمخزون
طلبات العملاء تبدأ `NEW` وغير مدفوعة، ويظهر مصدرها «متجر Auraic» في الداش. تجهيزها وشحنها وتسليمها يستخدم دورة الطلبات الحالية: خصم خامات الوصفة عند التجهيز، وتسجيل الدفع عند التسليم. لا يتم خصم المخزون أو تسجيل الإيراد بمجرد إرسال العميل الطلب. الكميات لا تُحجز في السلة؛ الإدارة تؤكد إمكانية تجهيز الطلب قبل الشحن.

الأسعار والشحن تُحسب من قاعدة البيانات في الخادم، ويُطلب من العميل مراجعة السلة لو تغير السعر قبل التأكيد. إعادة محاولة إرسال نفس الطلب لا تنشئ نسخة إضافية. الأصناف المخفية أو المؤرشفة أو التي لا تملك سعرًا ووصفة نشطة لا يمكن طلبها من الموقع. بيانات الوصفات والخامات والعملاء لا تُعرض في المتجر العام.

## الصور
رفع JPG/PNG حتى 3MB يحتاج متغيرات Cloudinary الثلاثة. يمكن أيضًا إدخال روابط HTTPS، حتى 8 صور للمنتج و8 بانرات. رفع الصورة وحده لا يحفظ النموذج؛ احفظ إعدادات المنتج/البانر بعد الرفع. الرسم الافتراضي للزجاجة توضيحي، ويُستبدل بصورة المنتج الحقيقية من الداش.

## التحقق
```bash
npm run typecheck
npm run lint
npm test
npm run build
```
GitHub Actions يشغّل أيضًا ترحيلات PostgreSQL، واختبارات الداش والموبايل، واختبار checkout عبر HTTP: السعر الصحيح، عزل المتاجر، منع شراء منتج مخفي، ومنع تكرار الطلب.

مجلد `mobile/` يحفظ تطبيق الإدارة الأصلي. توجيهه لهذه الاستضافة يحتاج بناءه باستخدام `--dart-define=API_BASE_URL=https://YOUR-AURAIC-DOMAIN`؛ ملف APK القديم يظل متصلًا باستضافته السابقة.

الدفع الإلكتروني، كوبونات الخصم وتكامل شركة الشحن ليست ضمن مسار الدفع الحالي. الطلبات الحالية تستخدم الدفع عند الاستلام ورسوم شحن موحدة قابلة للتعديل.

### الكوبونات

من «الكوبونات» في قائمة الداشبورد أو تطبيق الإدارة، أضف كودًا بنسبة أو مبلغ ثابت، مع حد أدنى للطلب/القطع، سقف خصم اختياري، قسم أو منتج، تاريخ بداية وانتهاء، وعدد استخدامات (0 = غير محدود). يمكن إيقاف الكوبون وتعديله أو حذفه. الشحن المجاني يعمل أيضًا بدون خصم مالي.

العميل يطبق كودًا واحدًا في ملخص الشيك أوت. الخصم على سعر البيع الحالي للمنتجات المؤهلة؛ حد الشحن المجاني العام يُحسب قبل الخصم. يُعاد التحقق من الصلاحية والسعر وعدد الاستخدامات داخل معاملة إنشاء الطلب. تأكيد الطلب يحسب استخدامًا واحدًا؛ إعادة المحاولة لا تستهلك استخدامًا إضافيًا، والمرتجعات لا تعيد استخدام الكوبون. كود الخصم وقيمته محفوظان في الطلب، وخصم الأصناف يدخل في حساب صافي المبيعات والربح.

قبل نشر هذه الإضافة، طبّق migration `20261004003000_coupons` على قاعدة الإنتاج باستخدام workflow «Apply production database migrations» أو `npx prisma migrate deploy`. لا تستخدم `db push` أو إعادة ضبط قاعدة البيانات. تحديث تطبيق الإدارة مطلوب لظهور صفحة الكوبونات على الموبايل.

### Product card badge

The optional badge text (up to 24 characters, for example `20% OFF`) is managed in the web and mobile product editor or web storefront settings. Empty text hides the badge; pricing remains controlled by the variant prices. Before deploying, run migration `20261004124000_product_badge` using the production migration workflow from this feature branch. Mobile users need an updated app build.
